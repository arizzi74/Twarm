# v0.7.31

Archive verification preserves each conversation's original Codex provider.
Previously an OpenAI session could export successfully but fail the isolated
resume check because the verifier tried to switch it to a custom offline
provider. The original project and conversation were retained.

The verifier now keeps the provider identity, redirects verification endpoints
to loopback, and uses a private file credential store. Built-in OpenAI is not
redefined, account credentials are not inherited, and project configuration
cannot override the isolated routing. Verification starts no model turns.

Compatibility pre-checks now use synthetic OpenAI conversations so this provider
restriction is exercised before archiving. Tests cover custom provider names,
project configuration precedence, malformed provider metadata, and Codex
0.163.0, 0.165.0 and 0.169.0. The previously failing archive also passes isolated
verification with unchanged archive bytes and original project files.

Archiving and deleting the original project still require successful verification
of the actual archive. Failed operations are not automatically resubmitted.
