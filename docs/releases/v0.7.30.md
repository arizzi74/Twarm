# v0.7.30

Codex session archives now check compatibility automatically. New runtime
versions can pass when their database schemas match a supported storage layout
and synthetic legacy and paginated conversations survive isolated export,
restore and restart. Codex 0.169.0 is covered without adding a version-only
exception.

Successful checks are cached in worker memory and bound to executable contents,
runtime version and live schemas. The WebUI shows compatibility-check progress
and distinguishes storage changes, unsupported conversation formats, changed
executables and failed isolated checks.

Every actual archive still requires its own restore verification before the
original conversation is archived or its project directory is removed. Restore
continues to require the original Codex version. Failed compatibility checks
preserve the existing session, project and archives.

Validation covers archive and restore safeguards with race detection, browser
session management, and native archive/delete/restore tests using Codex 0.163.0,
0.165.0 and 0.169.0. The focused release mode retains native archive proofs,
security scans, all-platform packaging and signed provenance without running
unchanged audio inference tests.
